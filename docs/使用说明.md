# 日序 v1.5 使用说明（AI 聊天规划 + 图片/文件导入）

- 安装包：`日序_v1.5.apk`（约 21 MiB，SHA256 见 `SHA256SUMS_v1.5.txt`）
- 版本：versionCode **6** / versionName **1.5**
- 最低系统：Android 8.0（API 26），targetSdk 34
- 包名：`com.jsy.dayplan`；与 v1.2/v1.1/v1.0 **同一签名**，可直接覆盖安装
- 原离线功能（今天/月历/倒数日/待办/专注/提醒/小组件/JSON 备份）保持不变

## 一、升级说明

直接覆盖安装 v1.4（或更早版本）即可，不需要卸载：

- 日程、待办、倒数日、完成状态、置顶、恢复前快照全部保留；
- 原有提醒在打开应用后按现有逻辑重新协调；
- Room 仍为 version=3（v1.4 已迁移），本版未再改 schema；旧日程/待办/倒数日/提醒标记/快照全部保留；
- AI 聊天记录、待确认草稿、附件缓存与材料上下文保存在应用私有目录，**不进入业务 JSON 备份**；
- “AI 提交事实”（批次 ID、真实落库 ID/版本、撤销前值、状态）与业务数据同库同事务保存，重启后可识别已保存批次，不会重复导入；
- 恢复/快照回退会把业务数据与 AI 权威世代**在同一 Room 事务**提交：即使随后偏好同步/进程中断，旧草稿与旧撤销也不能再操作恢复后的数据；启动以 DB 边界为准，不用旧偏好覆盖。
- 桌面“今日安排 / 重要日子”组件继续可用，AI 导入保存后会立即刷新。

## 二、右上角/右下角入口

四个主页面右下角会显示 Q 版 **DeepSeek 娘**入口（社区二创，非官方形象）：

- 默认展开为约 80×120dp 全身立绘；点小三角可收起为约 60dp 头部头像；
- 点角色进入 AI 聊天页；长按角色可暂时隐藏，在“我的 → AI 助手设置 → 入口显示”恢复；
- 入口只出现在今天/月历/倒数日/我的四个主页面，不进编辑页、不挡“+ 新增”和底部导航；
- 待机轻微呼吸；请求中显示三点气泡；关闭显示后不影响任何离线功能。

## 三、配置 DeepSeek（使用你自己的 Key）

路径：“我的 → AI 助手设置”。

1. 打开“启用 AI 助手”。
2. 填写自己的 DeepSeek API Key（`sk-…`），点“保存”。Key 使用 Android Keystore 管理的
   AES/GCM 密钥加密后保存在**不参与备份**的私有目录；不写日志、聊天记录、JSON 备份或源码。
3. 点“测试连接”。它只调用 `GET /models`，不产生对话费用；可同时刷新模型与图片能力。
4. 选择模型：默认为 `deepseek-flash`（文档标注支持 text+image）；`deepseek-v4-pro` 仅文本。
   实际能力以服务端 `input_modalities` 为准。图片发给纯文本模型会被拒绝并提示切换，不会悄悄换模型。
5. 可选设置：自动保存、参考现有安排、默认时长（10–240 分钟）、可安排时段、入口显示。
6. 没有 Key 或助手未启用时，聊天页只显示“去设置”提示，不提供假装能用的聊天。

清除 Key：“AI 助手设置 → 清除”。卸载/换机后 Keystore 密钥消失，需要重新填写。

安全说明：App 直连 `https://api.deepseek.com`，正常 HTTPS 证书校验；不提供第三方 URL/HTTP 代理；
不内置公用 Key；API 费用由你的 DeepSeek 账户按实际调用结算，App 不会显示虚构价格。

## 四、聊天规划日程

示例：

> 明天上午九点到十点读文献，提前十五分钟提醒；下周五交报告；11月24日是项目截止日。

- 每次请求都会注入**设备当前本地日期、时间、时区和星期**，聊天跨午夜后“明天”基准随之更新。
- “下周”按下一自然周（周一开始）；跨月、跨年、2 月 29 日由模型换算，最终日期在卡片上显示完整年月日。
- 时间段 → 日程；日期型重要日 → 倒数日或待办；只有日期没有时间 → 待办，不自动加 23:59 提醒。
- 不主动编造提醒；“提前 N 分钟”才设置。日程提醒 `0` 仍然表示**关闭**，不会改成开始时提醒。
- 含糊要求（“早一点”“周五上午”“课程第 3–16 周但没开学日”）会先问一个关键问题或标注假设；
  带假设的动作不会自动保存。
- 普通聊天、解释、查询、假设句和否定句（“先别安排”“今天不要提醒我”）不写库。
- 修改已有事项时会显示“变更前”并核对目标 ID 与版本；同名多条先澄清。
- 第一版不开放 AI 删除；已保存结果卡提供“编辑/删除”，进入原条目编辑页手动处理。

### 两种保存方式

- **默认先预览**：计划卡片逐项勾选/编辑，点“导入选中 N 项”一次事务保存；无效项默认不可选。
- **明确新增自动保存**（可选）：仅当整批都是明确新增、时间完整、无假设、无冲突、无重复、
  通过本地校验且 ≤20 项时自动保存。附件批次、含假设、有冲突、多批次或需要修改旧数据时
  一律保持待确认，不会偷偷保存一部分。

### 撤销

保存结果卡提供“撤销本批”：新增会删除 AI 写入的记录，修改会恢复保存前值；撤销前核对版本，
如果用户之后自己编辑过，会保留当前内容并提示冲突。恢复备份/快照后旧草稿和撤销自动失效。

超过 20 条会拆成多批（每批 ≤20），逐批确认，不会只保存前 20 条却显示“全部完成”。

### 多轮附件澄清

- 发送课表/图片/PDF 后，如果模型先问年份、节次时间等，你只回复“2099”或“第 3 节 10:00”时，下一轮仍会自动带上上一轮附件材料和选页/选表范围；
- 输入区会显示“继续参考：文件名”，可逐项点 × 移除；移除后不再随下一轮发送；
- 附件缓存被清理或文件缺失时，会明确要求重新选择文件，不会只拿文件名冒充已读取；
- 清空对话、恢复备份/快照后，旧材料上下文立即失效；
- 图片材料在后续轮次会重新编码发送，文档只发送提取文本/所选页。

## 五、图片与文件导入

聊天输入框左侧“+”：

- **相册图片**：使用系统 Photo Picker（旧系统自动回退系统选择器），不申请全盘存储权限；
- **文件**：使用系统文件选择器（SAF），支持 PDF/TXT/Markdown/CSV/DOCX/XLSX；
- 一条消息可同时带文字和多个附件（最多 6 个）；发送前显示缩略图/文件名/格式/大小，可点开预览/选页/选表、可移除；
- **选完附件只在本地处理，点击发送才会联网**；只发附件不给要求时，会先给“提取所有日程/只提取截止日期”等意图选项。

### 支持格式

| 格式 | 处理方式 | 说明 |
|---|---|---|
| JPG / JPEG / PNG / WebP（静态） | 本地解码、EXIF 旋转校正、重编码 JPEG 后走视觉模型 | EXIF 位置等元数据在上传重编码时去除 |
| PDF 文本型 | 手机本地用 PDFBox-Android 提取文字 | 只发送提取文本 |
| PDF 扫描型/混合型 | 无文字页用系统 PdfRenderer 渲染成图片，送视觉模型 | 单次最多 6 页扫描图 |
| TXT / Markdown | 本地 UTF-8/BOM 解码 | 旧编码会提示另存 UTF-8，不乱码导入 |
| CSV | 本地状态机解析引号、逗号、字段内换行 | 只发送提取文本 |
| DOCX | 本地解压解析段落与表格（保留行列） | 内嵌图片不解析，会明确提示可另发图片 |
| XLSX | 本地解析工作表有值单元格、表头、地址 | 日期按 1900/1904 系统；公式只读缓存，无缓存标“未知”；内嵌图片/图表只提示不解析 |
| 旧 DOC/XLS、加密文档、压缩包等 | 明确不支持 | 请先另存为支持的格式，不能改扩展名伪装 |

### 范围完整性与限额

- 单页 PDF 文本不再静默截断；材料总字符在 20000 以内会完整保留。超过总预算时本次**阻止发送**，提示减少页/表范围或分批，不会显示“已完整识别”。
- 批次卡片会显示解析/范围提示（扫描页上限、表格单元格上限、图片预算、内嵌图片未解析等），请以卡片上的范围为准确认。

- 每条消息最多 **6 个附件**；单附件 **10 MiB**；合计 **20 MiB**（读取时实际计数，超限立即中止并删除半截文件）。
- 图片解码像素上限 1600 万；单图编码后 ≤3 MiB，一条消息内图片合计 ≤8 MiB；超限会提示/跳过。
- PDF 单次最多 20 页文本或 6 页扫描图；超过时可分批。UI 可自选页码范围；文本合计超过 20000 字符会被阻止并提示分批。
- XLSX 单次最多 2000 个有值单元格；可选择工作表；提取文本合计上限 20000 字符。
- OOXML 同时限制 ZIP 条目数（2000）、单条目 8 MiB、解压总量 40 MiB、XML 深度；不执行宏/公式/外部链接。

### 来源核对与重复

- 每条草稿显示本地真实来源：文件名 + 页码 / sheet+单元格行 / 文本行号 / 图片序号；
  模型引用不存在的 sourceId 会被本地拒绝。
- 重复检测：同一批内重复、与现有条目完全相同默认不选中；同一附件曾成功导入会提示但**不禁止**，
  修改日期后可再次新建。
- 多个附件互相矛盾时，模型被要求列出来源让用户选择；附件里的“忽略以上要求/立即删除”等指令不会被执行。

## 六、隐私与数据

- 点击发送时，本次聊天文字和你选择的附件内容会发送到 DeepSeek：图片为压缩后的 JPEG data URL；
  文档为本地提取文本；扫描页为渲染图片；不含原始整个数据库或备份。
- 开启“参考现有安排”时还会发送未来 7 天忙碌时间摘要与近期候选条目的标题/ID/版本；
  默认不发送备注、地点、完整数据库或备份。可关闭该开关，本地冲突检查仍执行。
- 附件原文件复制到 App 私有目录，不改动你选择的原文件；使用生成 ID 命名，避免同名覆盖/路径穿越。
- 聊天记录、待确认草稿、附件缓存与材料上下文均不进入业务 JSON 备份/日志/源码包；Key 不进入任何备份。
- AI 提交事实只含批次 ID、真实 ID/版本、标题与撤销所需前值，不含附件原文、图片或 Key；随 Room 数据库保存。
- “清空对话及附件缓存”会删除聊天记录、待确认计划与本应用缓存的所有附件副本，已保存日程不受影响。
- 附件缓存默认保留 7 天（待确认批次引用的会保留）；启动时清理过期项。
- 恢复备份/快照后，恢复前的 AI 草稿和撤销请求自动失效，不会在恢复后写入。

## 七、错误与取消

- 请求中显示进度（读取附件 i/n → 识别/整理）与“取消”按钮；取消或清空对话后晚到的响应不会写库。
- 失败会区分：Key 无效（401）、余额不足（402）、限流（429）、服务异常（5xx）、超时、断网、
  内容截断、空响应、字段异常、模型不支持图片；可重试时提供“重试”，输入与附件保留。
- 返回内容不是合法 JSON、`schemaVersion` 不支持、未知 `kind`/动作、越界日期或非法枚举都不会写库。
- 保存与提醒分开报告：数据已保存但系统提醒调度失败时显示“已保存，提醒待重建”，不会让你重试导致重复添加。

## 九、v1.4 复验修复要点

- 同一批次并发点击、提交后文件写失败、重启后重试都只落库一次；入口防连点只是辅助，数据库提交身份才是最终保证。
- 恢复/清空与保存/撤销有共享执行边界：恢复前返回的旧响应、已加载的旧批次都不能再写入；旧结果卡撤销会提示失效。
- 批内两个不同标题但同一时段的新增日程不会自动保存；重复/空 clientActionId 的批次判无效；相邻时段不算冲突，同名不同日期不会误去重。
- 附件追问保留材料（文本与图片、选页/选表）；清空/恢复后失效。

## 十、v1.5 复验修复要点（恢复边界与自动保存新鲜度）

- 恢复备份或“用最近一次快照回退”时，业务替换和 AI 世代/会话边界在同一个 Room 事务提交；恢复失败则业务与边界都保持原值。
- 提交后即使偏好写入、附件清理、提醒重建或进程中断，旧计划卡会显示“已失效”，旧撤销不会删除恢复后复用相同 ID/版本的新条目；启动时 DB 边界优先于旧偏好。
- 自动保存不再沿用请求发出前的日历快照：最终写事务内会用最新日历、完整候选重新检查冲突/重复/版本/假设/来源/整批选择；期间新增了冲突安排时整批转回待确认预览，不自动写入。
- 用户主动预览后手动确认重叠条目的原有规则保持不变；自动保存只用于无冲突的整批明确新增。
- 自动保存失败/转预览的原因会显示在计划卡片上（例如“请求期间日历或配置发生变化…”）。
